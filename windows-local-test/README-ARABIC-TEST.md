# نظام التقارير المالية الموحدة — حزمة الاختبار المحلية (المرحلة 6.8)

حزمة اختبار محلية لـ Windows تعمل على **127.0.0.1 حصرًا** مع قاعدة بيانات اختبار معزولة.
هذه الحزمة **لا تلمس أي قاعدة إنتاج** — `custom.db` غير موجود فيها نهائيًا ولا يُشار إليه.

## ما الجديد في حزمة 6.8

- **طبقة طباعة موحدة** لكل التقارير: زر «طباعة / حفظ PDF» في القوائم الأربع وميزان المراجعة
  وفعلي مقابل موازنة والتقارير الموحدة — A4 رأسي أو أفقي حسب عرض التقرير، مع ترويسة تقرير
  موحدة (النظام، الشركة، السنة المالية، الفترة بالتواريخ الفعلية، العملة، نوع البيانات، حالة
  التقرير، تاريخ ووقت الطباعة) وتكرار رؤوس الجداول ومنع قص الصفوف في الطباعة.
- **مركز التقارير**: ملاحة موحدة على هيكل الشركة ← السنة المالية ← الفترة ← نوع التقرير
  مع روابط عميقة تفتح كل تقرير من مصدره المعتمد حصرًا.
- **تصدير CSV** لفعلي مقابل موازنة وورقة العمل الموحدة (يُفتح في Excel مباشرة بالعربية).
- عروض مُحسّنة: ترويسة تقرير موحدة + إشعارات صادقة للتوحيد الأولي (Preliminary) وINCOMPLETE_DATA.

## التشغيل

1. فك ضغط الحزمة في مجلد محلي.
2. شغّل `START-LOCAL-TEST.cmd` (نقرة مزدوجة).
   - يتطلب Node.js 20.9 أو أحدث (اختُبر على Node 24.x مع Prisma 6.x).
   - أول تشغيل يثبت الاعتماديات من `package-lock.json` عبر `npm ci` ثم يفحص/يولّد عميل Prisma
     **تلقائيًا** (فحص وظيفي عبر `scripts\verify-prisma-client.js` — لا `npx` ولا خطوات يدوية).
   - أول تشغيل يترجم التطبيق — انتظر ظهور سطر Ready ثم افتح المتصفح.
3. افتح `http://127.0.0.1:3000` (أو 3001 إن كان 3000 مشغولًا — السكربت يبدّل تلقائيًا).

### بيانات الدخول (اختبار حصرًا)

- المستخدم: `admin`
- كلمة المرور: `Preview-68-Admin!`

⚠️ هذه بيانات اختبار معلنة عمدًا داخل حزمة معزولة على localhost — **لا تُستخدم في أي بيئة إنتاج**.

## قاعدة الاختبار المعزولة

- الملف: `db\phase68-local-test.db` (نسخة نظيفة احتياطية: `db\phase68-local-test.backup.db`).
- أعيد بناؤها من migrations المخطط حصرًا ثم بُذرت عبر `scripts\seed-local-test.ts`
  (شركتان: SHARIK-1 / SHARIK-2، سنة 2026، قواعد تصنيف، ميزان مراجعة معتمد،
  موازنة معتمدة، مجموعة توحيد أولي).
- لإرجاع القاعدة لحالتها الأولى: شغّل `RESET-LOCAL-TEST.cmd`.

## المسار الوظيفي المقترح للتجربة

1. **لوحة المعلومات** — حالة أحدث ميزان معتمد وعدد الحسابات غير المصنفة.
2. **مركز التقارير** — اختر الشركة والسنة والفترة ثم افتح أي تقرير من البطاقات.
3. **القوائم المالية** — ربح وشامل / مركز مالي / حقوق ملكية / تدفقات نقدية، ثم
   «طباعة / حفظ PDF» (A4 رأسي) — راقب الترويسة الموحدة وحالة المعتمد.
4. **الموازنة والمقارنات ← فعلي مقابل موازنة** — اختر الشهر/الربع/YTD ثم
   «تصدير CSV» و«طباعة / حفظ PDF» (A4 أفقي).
5. **التقارير الموحدة** — ولّد التقرير للمدى 2026-01-01 → 2026-03-31: لاحظ شارة
   PRELIMINARY وINCOMPLETE_DATA لعضو بلا بيانات (لا صفر صامت) وأعمدة الاستبعادات
   المنفصلة، ثم صدّر ورقة العمل CSV أو اطبعها A4 أفقي.
6. **ميزان المراجعة** — افتح تفاصيل الميزان المعتمد ثم «طباعة / حفظ PDF» (A4 أفقي)
   — بيانات الحوكمة (رقم المراجعة، السبب، الاعتماد) تُطبع أيضًا.

## حدود هذا الاختبار (موثقة عمدًا)

- التوحيد أولي (Preliminary): لا NCI/شهرة استحواذ/محاسبة استحواذ/فروق عملة — مراحل لاحقة.
- PDF عبر محرك طباعة المتصفح في هذه المرحلة؛ تصدير PDF/Excel/Word أصلي مرحلة لاحقة
  (طبقة التصدير `lib/report-export.ts` هي نقطة التوسع الوحيدة المطلوبة).
- لقطات تقارير معتمدة غير قابلة للتغيير (immutable approved snapshots): مرحلة لاحقة.
