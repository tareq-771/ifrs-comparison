# نظام التقارير المالية الموحدة — حزمة الاختبار المحلية (المرحلة 6.7)

حزمة اختبار محلية لـ Windows تعمل على **127.0.0.1 حصرًا** مع قاعدة بيانات اختبار معزولة.
هذه الحزمة **لا تلمس أي قاعدة إنتاج** — `custom.db` غير موجود فيها نهائيًا ولا يُشار إليه.

## ما الجديد في حزمة 6.7

- **إصلاح `prisma generate` اليدوي**: كان إصدار 6.2D يكتفي بفحص وجود مجلد العميل، فمرّ عميل قديم
  واضطر المستخدم لتشغيل `prisma generate` يدويًا. الآن يوجد فحص **وظيفي**
  (`scripts\verify-prisma-client.js`) يتحقق من تحميل العميل ومن وجود نماذج المخطط كاملة
  (أحدثها `ConsolidationGroup`)، ويُعيد التوليد **تلقائيًا** عبر النسخة المحلية المثبتة
  (`node_modules\.bin\prisma.cmd`) عند الحاجة — بلا `npx` وبلا أوامر يدوية.
- واجهة استخدام جديدة كاملة (لوحة معلومات، ميزان مراجعة، قوائم مالية، موازنة وفعلي مقابل موازنة،
  تقارير موحدة أولى، أدوات مقارنة سابقة).

## التشغيل

1. فك ضغط الحزمة في مجلد محلي.
2. شغّل `START-LOCAL-TEST.cmd` (نقرة مزدوجة).
   - يتطلب Node.js 20.9 أو أحدث (اختُبر على Node 24.x مع Prisma 6.x).
   - أول تشغيل يثبت الاعتماديات من `package-lock.json` عبر `npm ci` ثم يفحص/يولّد عميل Prisma تلقائيًا.
   - أولا تشغيل يترجم التطبيق — انتظر ظهور سطر Ready ثم افتح المتصفح.
3. افتح `http://127.0.0.1:3000` (أو 3001 إن كان 3000 مشغولًا — السكربت يبدّل تلقائيًا).

### بيانات الدخول (اختبار حصرًا)

- المستخدم: `admin`
- كلمة المرور: `Preview-67-Admin!`

⚠️ هذه بيانات اختبار معلنة عمدًا داخل حزمة معزولة على localhost — **لا تُستخدم في أي بيئة إنتاج**.

## قاعدة الاختبار المعزولة

- الملف: `db\phase67-local-test.db` (نسخة نظيفة احتياطية: `db\phase67-local-test.backup.db`).
- أعيد بناؤها من migrations المخطط حصرًا ثم بُذرت عبر `scripts\seed-local-test.ts`
  (شركتان: SHARIK-1 / SHARIK-2، سنة 2026، قواعد تصنيف، ميزان مراجعة معتمد،
  موازنة معتمدة، مجموعة توحيد أولي).
- لإرجاع القاعدة لحالتها الأولى: شغّل `RESET-LOCAL-TEST.cmd`.

## المسار الوظيفي المقترح للتجربة

1. **لوحة المعلومات**: حالة آخر ميزان معتمد + اختصارات.
2. **ميزان المراجعة**: استعراض الميزان المعتمد المبذور، أو رفع ملف جديد من `sample-data\`
   (اختر نوع البيانات صراحةً: تراكمي YTD أو حركة فترة).
3. **القوائم المالية**: ربح وخسارة + دخل شامل / مركز مالي / تغيرات حقوق الملكية / تدفقات نقدية —
   مع تفصيل الحسابات داخل كل بند (اضغط اسم البند).
4. **الموازنة والمقارنات**: موازنة معتمدة مبذورة + فعلي مقابل موازنة (جرّب «ربع سنوي» مع الرقم 1).
5. **التقارير الموحدة**: مجموعة النموذج (SHARIK-1 + SHARIK-2) — لاحظ أن الشركة الثانية بلا بيانات
   فتظهر INCOMPLETE_DATA صراحة (لا أصفار صامتة) والتقرير موسوم «توحيد أولي PRELIMINARY».
6. **الإدارة**: الشركات والسنوات المالية، دليل الحسابات والتصنيف، المستخدمون، التدقيق، النسخ.

## الأمان

- الخادم يستمع على 127.0.0.1 فقط.
- `NEXTAUTH_SECRET` يُضبط داخل السكربت بقيمة اختبارية لمرة واحدة.
- السكربت يرفض أي مسار قاعدة يحتوي `custom.db` (حارس أمان في START وفي فاحص Prisma).
- لا تُنقل هذه الحزمة إلى خادم عام ولا تُستخدم لإنتاج.

## متطلبات

- Windows 10/11، PowerShell أو CMD (السكربتات .cmd تعمل بالنقر المزدوج).
- Node.js 20.9+ (لا حاجة لـ Bun — الاعتماديات عبر npm من الملف المجمد).
- لا تغييرات على الشبكة أو جدار الحماية.
